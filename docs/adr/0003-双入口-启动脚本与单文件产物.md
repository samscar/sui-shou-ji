# 双入口：日常用启动脚本跑本地服务，单文件产物转为分发

Status: accepted

## 背景与决策

ADR-0001 把单文件产物确立为唯一入口，随之暴露一个摩擦：改一行源码后必须先跑
`npm run build:standalone` 重建，双击打开的才是新版。日常迭代时这一步很容易忘，
表现为"改了代码但页面上没变化"。

改为**双入口**：

- **日常：双击 `启动应用.command`** —— 脚本起 Vite 开发服务器并打开浏览器。
  改源码后热更新自动生效，不存在"忘记重建"这回事。
- **分发：单文件产物 `web-app/dist/index.html`** —— 保留，用于发给别人或没装 node 的机器。

同时补上一个脚本才能成立的前提：本机 node 不在系统默认 PATH 里，所以脚本不能裸写
`npm run dev`，必须自己探测 node 的绝对路径，并在依赖缺失时自动安装、端口冲突时自动顺延。

## 为何不反过来取消单文件产物

脚本路线依赖 Node 环境和 5173 端口，在别人机器上不成立；单文件产物只有一个文件、
双击即用，是唯一能直接发出去的形式。两者覆盖的场景不同，不是二选一。

## 后果

- **localStorage 按 origin 隔离**：`http://localhost:5173` 与 `file://` 是两笔互不相干的
  用户修改。在单文件入口积累的修正不会出现在本地服务里，反之亦然。跨入口搬运必须走
  「导出我的修改 → 导入配置」。这一条已写入 README。
- ADR-0001 中关于"日常形态"的表述被本决策调整，技术部分不受影响。
- 脚本需要可执行权限（`chmod +x`），且首次双击会被 macOS Gatekeeper 拦截一次。
