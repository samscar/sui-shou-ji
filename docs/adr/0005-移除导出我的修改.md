# 移除「导出我的修改」

Status: accepted

## 背景与决策

「管理分类映射」里原有四个按钮：直接编辑分类表、导出我的修改、导出分类表、导入配置。

「导出我的修改」导出的是 `customMappings` + `editedRecords` 的完整快照，是唯一能带走
**交易修正记录**的文件形态。移除它，只保留「导出分类表」。

## 代价（必须知情）

交易修正记录从此**没有任何文件形态**。它是按「原始备注 + 交易日期」索引的逐条修正，
无法还原成关键词规则，因此「导出分类表」带不走它。移除后：

- 换设备、换浏览器、清除浏览器数据 → 修正记录全部丢失，无恢复手段。
- 两个入口（`http://localhost:5173` 与 `file://`）之间的数据依然互不相通，
  但也不再有任何搬运办法。
- 重新解析时，那些修正过的记录会退回关键词匹配的结果。

这与 ADR-0002「用户修改只存浏览器本地」和 ADR-0003「双入口」中
「导出我的修改 → 导入配置」的迁移路径直接冲突。那两份 ADR 的相关表述以本决策为准。

## 考虑过的其他方案

- **保留但降到二级菜单**：用户明确要求删除该入口，不是要求少看见它一次。
- **把修正记录并入分类表快照**：`EditedRecord` 与分类表是两种结构（前者逐笔、
  后者是关键词规则），硬塞进 `categories.json` 会让该文件既不是分类表也不是用户数据，
  且既有导入逻辑按 `expendCategories` 是否存在来判别格式，会误判。

## 后果

- 「导入配置」仍保留，仍能接受旧版导出的用户修改文件——历史备份不会失效。
  但界面不再提供生成该文件的入口。
- 配置管理区块的提示文案改为「自定义映射词条保存在本浏览器中」，
  不再承诺「换设备时导出后在另一台设备导入即可恢复」。
