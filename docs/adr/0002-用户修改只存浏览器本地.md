# 用户修改只存浏览器本地，不写回产物文件

Status: accepted

## 背景与决策

用户的积累（自定义映射词条、交易修正记录）全部存放在浏览器 localStorage，单文件产物本身
不承载任何用户数据。分类表编辑器的「保存并生效」也写入 localStorage，而不是改写
`src/config/categories.json`。

后者是对单文件交付形态（ADR-0001）的直接让步：原先的流程要求用户下载 `categories.json`
再覆盖 `web-app/src/config/categories.json`，而双击 HTML 的使用者根本没有源码目录，这条路径
不可达。改为就地生效后，"编辑 → 应用"在使用者视角才闭环。

代价是数据与浏览器绑定。为此把导出拆成两类：「导出我的修改」是跨设备迁移的正确载体
（也是唯一能带走交易修正记录的一种），「导出分类表」只用于查看和分析全量分类规则。

## 后果

- 清除浏览器数据会一并清除用户修改，需要用户主动导出备份。
- 本机同一浏览器的不同标签页共享修改；换浏览器或换设备不会同步。
- 后续若要真正同步，需要另立决策（例如引入云服务或文件系统存储），不是靠构建配置能解决的。
