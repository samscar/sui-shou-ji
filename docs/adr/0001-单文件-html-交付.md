# 交付形态为自包含的单文件 HTML

Status: accepted

## 背景与决策

应用原本只能通过 `npm run dev` 启动后访问 `http://localhost:5173/`，使用者必须开着终端。
改为以**单文件产物**（`npm run build:standalone` 产出的 `dist/index.html`，JS/CSS 全部内联）
作为日常使用方式，双击即可用 Chrome 打开；`npm run dev` 保留给开发。

这不是"改一行配置"能达成的：在 `file://` 协议下，浏览器对外链的 `<script type="module">`
按 opaque origin 施加 CORS 限制，直接拒绝加载。因此仅把 `base` 改成 `'./'` 产出相对路径的
多文件版本依然会白屏——必须把脚本内联成普通 `<script>`。这正是引入
`vite-plugin-singlefile` 的原因，也是为什么保留了两种构建形态而不是合并成一种。

## 考虑过的其他方案

- **双击 `.command` 启动脚本**：改动最小，但仍要求 Node 环境、会弹终端窗口、占用端口，
  没有真正解决"不想开命令行"这个诉求。
- **相对路径多文件产物**（`base: './'` + IIFE 格式）：交付物是一个 HTML 加一个资源文件夹，
  搬运时容易散落丢失，且 IIFE 改造比内联方案更容易出问题。

## 后果

- 产物从多文件变成单个约 760 KB 的 HTML，已纳入版本控制，多设备靠 `git pull` 分发。
- 使用者不再需要 Node 环境，可以直接把文件发给任何人。
- 单文件是**只读的容器**：用户的积累不写回该文件，见 ADR-0002。
