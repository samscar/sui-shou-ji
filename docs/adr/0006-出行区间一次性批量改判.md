# 出行区间：一次性批量改判支出分类

Status: accepted

## 背景与决策

一次外出（旅游、出差）期间的花销，散落在购物、餐饮、打车、其他杂项等七八个分类里。
想回答"这趟一共花了多少"，只能逐笔手工改分类。一份真实流水在 2026-10-01 ~ 10-06
有 67 笔支出 ¥14,894.37，其中 44 笔 ¥2,233.28 落在「其他杂项」，正等人一条条点。

决策：允许用户手动选择一个**出行区间**（起止日期），把区间内的支出整体改判为
「出差旅游 / 其他消费」。

四条边界：

1. **一次性，不落盘。** 区间只存在本次会话的内存里，不写进用户修改，刷新即失效。
2. **只改支出，不改收入与转账。** 区间内两笔工资（共 ¥47,000）保持「职业收入 / 工资收入」。
3. **居家支出不改判。** 房贷、物业水电、手机话费、网购与超市采买这四个主分类
   （金融保险、居家生活、交流通信、购物消费）原样保留。判断依据是**主分类**，不是摘要——
   流水里没有可靠的"消费/非消费"标记（`消费`、`充值`、`跨行转出` 混杂，9-30 的
   -560.00「跨行转出/红包」其实是真消费）。购物消费也在其中，理由见下。
4. **改判结果必须看得见、撤得回。** 单独一张「区间归类清单」列出每一笔被改判的支出
   （日期、金额、原分类、备注），逐条可「不计入」，也可恢复。与剔除清单同构。

同一个区间在上述口径下改判 **54 笔 ¥3,119.07**，剩下 13 笔 ¥11,775.30 不动，其中包括
10-02 房贷 ¥10,400.00、10-01 话费 ¥199.59，以及 11 笔购物消费 ¥1,175.71。

## 为什么不做成保存的规则

第一版方案考虑过把它做成跟随用户修改一起存下来的规则（像自定义映射词条那样），
下次解析自动套用。放弃的理由：

- **出行不是每月都发生的事。** 保存下来的规则会一直躺在配置里，成为"以后可能有用"
  的负担；而区间本身极易重填（两个日期）。
- **一次性让优先级问题消失。** 若区间持久化，它就会和交易修正记录长期争夺同一条流水
  的归属，需要一套用户看不见的优先级规则。一次性则没有这个问题：区间只在本次会话里
  覆盖，撤销一次即回到修正记录给出的分类。

代价必须知情：**刷新页面、切换文件、重新导入，区间都要重选。** 在这一点上它和
剔除清单里"恢复了哪几对"是同一类状态——会话内的临时选择，不做持久化。

## 为什么排除居家支出，而不是按摘要筛"消费类"

按摘要筛的做法在这份真实流水上站不住：

- `摘要 = 跨行转出` 既包含还房贷（真支出），也包含红包（真支出），还包含真正的跨行转账；
- `摘要 = 充值` 的 8 笔全是扫码付款给个人（336、253、155、126…），是旅途中的真实花销；
- `摘要 = 消费` 覆盖了绝大多数，但会漏掉上面两类。

按主分类判断则有一句话可复述的标准：**钱花在家里，不花在路上。**
房贷、物业水电、手机话费、网购与采买都花在家里；餐饮、打车、门票、住宿花在路上。

**购物消费归入居家支出**，是因为旅途期间的网购是日常行为，不因下单地点在酒店就变成旅游花销。
这份流水里区间内的 11 笔购物消费 ¥1,175.71，8 笔是淘宝/天猫的单（床垫 ¥394.40、物资 ¥470.79、
电器 ¥70.00…），收货地址都在家里。若把它们算进旅游支出，"这趟花了多少"会虚高三分之一。

代价必须知情：整类排除会连带排掉**路上的采买**——区间内的便利店 ¥5.00 与土地工 ¥25.38，
合计 ¥30.38，这两个是旅途中真实发生的支出，但会留在购物消费里。要用关键词把"网购"与
"在路上买水"分开，就得在"主分类在不在集合里"这条一句话规则之外再加一层判断；为 ¥30.38
破坏规则的完整性不划算，接受这个误差。

## 考虑过的其他方案

- **只把「其他杂项」改判，已有明确分类的不动。** 放弃。这样区间内仍会有 22 笔散在
  购物、餐饮、打车、交通费科目里，"这趟花了多少"永远算不出来——而这正是本功能的唯一目的。
- **把区间并进分类表快照一起导出。** 放弃。快照的语义是"分类表的全量副本"，
  塞进区间会让它既不是分类表也不是用户数据（与 ADR-0005 同一理由）。
- **区间内逐笔点选，不做区间。** 放弃。44 笔要 44 次点击，这正是要消除的成本。

## 后果

- 界面从一个纵向长页改为 Tab：概览 / 待分类 / 退款剔除 / 转账 / 出行区间。
  出行区间排在最后——它是偶发操作，不是每月必经的步骤。
- 区间生效时，被改判的记录从「待分类记录」表格里消失。区间归类清单是它们唯一的入口，
  所以这张清单不是可选的附加物，是这个功能能成立的前提。
- 区间只影响解析结果的分类，不改变金额，因此统计卡里的支出合计不变。
- 本次同时把 `App.tsx` 按 Tab 拆成组件（`src/components/`），解析与导出逻辑不动。
